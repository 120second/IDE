# 2026 年 10 月审查修复

处理前已将社区功能及当时的工作区状态提交至 GitHub：`5b1ce0f`。

## 本次处理

| 问题 | 实现 |
| --- | --- |
| 大量输出后停止可能卡住 | 回收 Windows Job Object 中的进程，持续排空有界输出队列后再等待读取线程；限制每轮排空量，确保停止和超时能够执行 |
| 文件改名后关联数据丢失 | 在归档迁移的 SQLite 事务内迁移测试点、生成规则、题面、批注和画板；前端同步迁移 PDF，兼容文件夹、中文和仅大小写变化 |
| 浏览器存储配额失败被忽略、旧笔记自动删除 | 文字和笔迹迁入 SQLite，不再按记录数量自动淘汰；保留旧数据，迁移事务只执行一次；写入失败提示、保留最新快照重试，未保存成功时阻止正常退出 |
| PDF 在事务提交前显示保存成功 | 等待 IndexedDB 事务提交，处理中止和错误；迁移保留原 PDF 键作为读取回退 |
| 私信异步响应串到另一会话或退出后回填资料 | 校验账号、请求代次和收件人，切换会话立即清空旧列表，保留新输入的草稿 |
| 只显示最近 80 条消息且旧未读无法清除 | 以时间和消息 ID 做稳定游标分页；打开会话后清除已读水位之前的未读，刷新时合并已加载历史 |
| 中文输入法确认文字时发送消息 | 忽略 composition 状态下的 Enter |
| 编译任务不能取消且没有超时 | 在工作线程排队前登记可取消任务，设置 120 秒上限；取消/超时回收编译子进程并清理半成品，对拍编译也共享停止标志 |
| 登录、注册和私信缺少请求限制 | 按 IP 使用滑动窗口，登录另按规范化账号限制、发信另按用户限制；内存键数量有上限，返回 429 |
| 缺少持续检查和格式一致性 | GitHub Actions 检查前端、Rust、真实 C++ 工具链、Python 与数据库迁移，并构建 Windows Release；统一 Rust 格式 |

## 数据和部署

- 本地数据库升级至第 9 版，不删除旧版 `localStorage` 内容；迁移失败可重试。文字、笔迹迁移完成后以 SQLite 为准。
- PDF 仍在 WebView IndexedDB。备份时需要同时保存应用数据和 WebView 数据目录，不能只复制 SQLite。
- 文件改名会移动关联数据。复制文件仍产生新文件，不自动复制题面或测试点。
- 本地服务端修复需要部署更新后，客户端分页和请求限制才完整生效。此次代码同步不等于远程服务器部署。
- 请求限制适用于当前单 worker 部署；多 worker/多实例部署时应改用共享存储的限流器。
- 登录 IP 限制为 15 次/分钟、账号限制为 20 次/5 分钟；注册 10 次/10 分钟；忘记密码 5 次/5 分钟；重置密码 15 次/5 分钟；发信 IP 30 次/分钟、用户 20 次/分钟；其他请求 IP 600 次/分钟。私信轮询不计入发信窗口。
- Windows 通过 Job Object 终止进程树；其他平台当前只保证直接子进程退出，项目仍以 Windows 为目标。

## 后续功能候选

这些是后续设计方向，尚未实现：

1. 自动最小化反例：按数组元素、图边或输入行尝试删除与缩减；只有仍复现原失败时保留修改，并设时间预算。
2. 失败重放包：打包随机种子、生成规则、代码、编译参数、输入及双方输出，在另一台机器重现对拍失败。
3. 题目训练复盘：结合归档标签、错误类型和历史测试结果，记录高频薄弱点与待复习题目。

优先建议先做失败重放包，再做最小化反例；重放包能为最小化过程提供稳定的失败判定环境。
