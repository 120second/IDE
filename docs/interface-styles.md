# 界面风格与测试框

在“设置 → 界面 → 界面风格”中，可切换 LightCP、经典 IDE 和 Sublime 风格。

- LightCP 保留原来的工作台，已有的主题、字体和背景设置继续保留。
- 经典 IDE 使用灰色面板、蓝色按钮、顶部菜单、文件搜索，以及支持点击和键盘跳转的代码缩略图。也支持浅色模式。
- Sublime 风格使用黑灰半透明背景、文件树，以及粉红关键字、绿色类型、淡黄字符串的 Monokai 风格代码配色。功能集中在顶部菜单，也支持浅色模式。将编辑器配色设为“跟随界面主题”即可使用对应的代码配色。
- LightCP 和经典 IDE 的“测试框风格”可以跟随界面，或单独选择 LightCP 标准、经典紧凑双栏。紧凑风格将输入和期望输出并排显示，程序输出独占下一行。

测试框展开使用 140 毫秒的缓出动画，按钮使用短暂的颜色反馈。输入时不再反复重算文本框高度，可通过右下角手柄调整高度。排序使用单独的拖动手柄，也支持 Alt+↑/↓；点击标题只展开或收起。

“减少动态效果”和性能模式会关闭展开动画。收起、重新展开以及切换界面不会丢弃当前测试框中的编辑内容。运行前会保存正在编辑的对应测试点。

测试框中的运行时限仍为所有测试点共用的设置。

## Sublime 右侧工具

Sublime 左侧固定显示文件夹树。右侧只保留“测试点”和“题面”，页面标签与顶部代码文件标签在同一行。选择、宽度与显示状态会保存到下次启动。旧版本的 in / out 页面会自动迁移到测试点；已有的 in.txt、out.txt 文件继续保留在磁盘中。

- **测试点**：CPH / FastOlympicCoding 风格的紧凑灰色矩形按钮。第一行是 `test 0 / edit`，下一行是 `run / time`，下方 `next test` 定位下一个测试点或新建。支持编辑输入和期望输出、运行前保存、全部运行、判定和输出查看。`Ctrl+Enter` 新建测试点。期望输出为空时只运行，不比较答案。
- **题面**：保留 Markdown / PDF 阅读、导入、编辑、批注和样例导入功能。切换页面时保留草稿；从题面导入样例会定位到右侧测试点。

Sublime 下“编译并运行”（F5）使用当前文件已启用的测试点。右侧面板左边缘可以拖动调整宽度；隐藏后从“工具”菜单重新打开测试点或题面。标准 / 双栏测试框选择会保留供其他界面使用。

Windows 窗口已启用原生透明背景；Sublime 的编辑区、文件树、测试点和题面共用一层半透明底色，文字保持清晰。实际透出的内容取决于窗口后方的桌面或窗口。在“设置 → 界面 → Sublime 风格 → 整体透明度”中可实时调整并自动保存，默认 3%；0% 为完全不透明，100% 为背景全透明。支持滑块和数值输入，也可一键切到完全不透明或恢复默认。整体透明度独立于旧编辑区设置，旧版本升级后使用新的 3% 默认值。其他界面继续显示原有不透明背景。

界面参考：[FastOlympicCoding 官方项目](https://github.com/Jatana/FastOlympicCoding)。
