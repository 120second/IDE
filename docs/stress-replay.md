# 对拍反例重放包

对拍发现反例后，可点击“导出重放包”保存 `.lightcp-replay.json`。包中包含编译时读取的两份 C++ 源码、应用版本、随机种子、生成规则、编译参数、运行限制，以及原始输入、双方输出、错误输出、退出码和统计。

在对拍页面点击“导入并重放”，选择该文件。LightCP 使用当前设置里的编译器，在应用数据目录的独立临时目录中编译包内源码，直接运行包内输入。随机生成规则不会重新生成输入，当前工作区源文件也不会被写入。正常完成、停止或编译失败后都会尝试清理临时目录。

结果不一致时显示此次失败原因；结果一致时保留双方输出，并明确显示“本次重放输出一致”。重放结果可以再次导出。重放模式中的“保存为测试点”“调试此用例”和“继续对拍”不会操作当前工作区中不相关的代码文件。

编译标准与 Release 参数沿用包内记录，编译器路径使用当前电脑的设置。不同编译器、标准库、优化参数或系统可能影响结果；重放包不会保证跨平台得到完全相同的行为。

当前重放包面向独立源码的竞赛题：保存两份源文件，不收集自定义头文件、其他翻译单元、编译插件或外部资源。如果源码依赖这些内容，需要另行提供相应文件并调整编译参数。包内源码保持原文，包括其中引用的绝对路径。

格式版本为 1。导入文件上限为 96 MiB，单份源码上限为 16 MiB；只接受指定格式与版本。导出采用临时文件和原子替换，校验失败不会覆盖已存在的重放包。编译期间源文件变化会中止正常对拍，避免输出与源码快照不对应。

第二轮同时修复了对拍事件的 `sessionId` 序列化、保存源码时重复启动/停止、工作线程排队前取消，以及 clangd 工作区、诊断路径和对拍源码快照工作区的规范化问题。Windows 临时目录的短路径别名与包含 `..` 的工作区路径也可正确处理。
